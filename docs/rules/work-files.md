# 작업 파일 규칙

여러 단계로 진행하는 작업의 범위, 완료 기준, 검증 결과를 `docs/work/`에 파일 하나로 남긴다.

## 위치와 이름

- 앱이 어디든 루트 `docs/work/` 한 곳에만 둔다. 앱별 `docs/`에는 작업 파일을 두지 않는다.
- 파일 이름은 `<Jira 티켓>-kebab-case.md`다(예: `KD3-644-backend-dev-setup.md`).
- 만들면 [docs/README.md](../README.md)의 `work/` 행에서 찾을 수 있어야 한다.

## 양식

```markdown
---
title: 제목
status: 진행 전 | 진행 중 | 완료
created: YYYY-MM-DD
updated: YYYY-MM-DD
---

# 제목

## 목표와 범위 (범위 밖 포함)

## 단계 (체크리스트 + 완료 기준)

## 검증 기록 (항목 / 실행 명령 / 결과)

## 남은 결정·후속 작업

## 변경 기록 (날짜 — 무엇을 → 무엇으로, 이유)
```

## 쓰는 방법

- 완료 기준은 "명령을 실행하면 무엇이 통과한다"처럼 확인 가능하게 쓴다.
- 검증은 실제로 실행한 명령과 결과를 적는다. 실행하지 않은 항목은 "미실행"으로 두고, 실행했다면 "미실행"을 실제 명령과
  결과로 바꾼다.
- 실패한 검사도 지우지 않고 남긴다. 결과 칸에 "실패: 원인 → 조치 후 통과"처럼 적고, 길면 표 아래에 짧게 덧붙인다.
- 계획이 바뀌면 무엇을 왜 바꿨는지 "변경 기록"에 한 줄로 남긴다. 작업 중 인수인계와 PR 리뷰에서 계획과 결과의 차이를
  설명하는 용도이며, 오래 남길 결정은 ADR로 옮긴다.
- 작업 중 확정된 결정은 그 자리에서 [ADR](../adr/README.md)이나 [API 공통 규약](../api-conventions.md)에 옮기고, 작업
  파일에는 링크만 남긴다.

## 작업이 끝나면

1. 결정이 ADR·규약·앱 문서에 반영됐는지 확인한다.
2. 끝내지 못한 일은 새 Jira 티켓이나 새 작업 파일로 넘긴다.
3. 작업 파일은 마지막 커밋이나 PR에서 삭제한다. 이력은 git, PR, Jira가 남긴다.
