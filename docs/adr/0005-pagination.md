# 0005. 페이지네이션은 page/size

## 맥락

백오피스에는 문의, 아이디어 제안, 변경 이력 같은 목록 화면이 많다. 목록 API의 요청과 응답 모양을 정해야 한다.

## 결정

page/size(offset) 방식을 쓴다.

- 요청: `GET /users?page=2&size=20`
- `page`는 1부터 시작하고, `size`의 기본값은 20, 최대값은 100이다.
- 응답: `{ items, page, size, totalItems, totalPages }`

## 근거

- 관리자 목록은 페이지 번호가 있는 테이블, 검색, 필터가 일반적이다. 웹이 이미 쓰는 `nuqs`로 `?page=2`를 URL 상태에
  연결하기 쉽고, 조회는 일반 `useQuery`로 단순하게 구현된다.
- 데이터 규모가 offset 방식의 성능 문제가 드러나기 전이다.
- `size`의 최대값이 없으면 `size=100000` 같은 요청으로 서버에 부하를 줄 수 있다.
- 응답 필드를 `items`로 쓰면 "응답을 감싸지 않는다"는 규칙([ADR 0004](0004-response-and-error-format.md))과 혼동되지
  않는다.

## 검토한 대안

cursor 방식은 대용량과 무한 스크롤에 적합하지만 총 개수 표시가 어렵고 URL에 두기 불편하며 구현이 더 어렵다.

## 결과와 후속

로그성 목록(변경 이력)이 크게 쌓이면 그 목록만 cursor 방식을 따로 검토한다. 정렬과 필터 규칙은 첫 목록 명세 전에 정한다.
