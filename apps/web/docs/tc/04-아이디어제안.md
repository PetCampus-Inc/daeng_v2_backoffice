## 사용성 검증 (2026-10-22)

근거: 사용자 요청에 따른 누락 점검 및 CONTRIBUTING.md 「화면 작업의 사용성 검증과 완료 기준」. 아래 항목은 기존 기능
TC를 보완하는 조작 품질 기준이며 새로운 PRD 기능 요구사항이 아니다. TC 추가는 실행 완료를 뜻하지 않는다. 실행 시 정상
응답과 명시된 지연·실패 조건을 각각 확인하고, 중간 DOM·요소 위치·포커스·스크롤 관찰 및 trace를 `.local/test-results/`에
남긴다. 지각적 깜빡임·배치 품질은 자동 검사와 별도로 브라우저에서 관찰한다.

회귀 검사: `apps/web/e2e/support-usability.ts`. 실행 환경·명령은 [E2E 실행 안내](../browser-test-running-guide.md)를
따른다. 계정 전환 중 이전 결과 노출 방지는 `src/routes/ideas/api/ideas/ideas.test.ts`에서 함께 검사한다. 실제 OS IME와
운영 서버 반영은 별도 확인 대상이며 CDP 조합 이벤트·가짜 API 통과로 대신하지 않는다.

### S-제안-019. 연속 검색·한글 조합 중 마지막 입력과 초점을 유지한다

- 시작: 아이디어 제안 목록

  - 실제 IME 조합 품질은 별도 브라우저 관찰로 기록하고 단순 문자열 입력으로 대체하지 않는다

  - 복귀 시 검색·유형·정렬·페이지가 일치하고 읽던 행의 스크롤·초점 맥락을 회복한다
  - 조회 전용 화면 이동에 불필요한 이탈 확인창이 뜨지 않는다

### S-제안-022. 상세 조회 실패 후 같은 제안으로 복구한다

- 실행: E2E
- 로그인: 조회자
- 데이터: `제안-기본`
- API: #350 상세 조회 1.5초 지연 후 500, 재시도는 정상. 별도 경우 404
- 시작: 제안 상세(#350)
- 행동: 상세 조회 실패 후 [다시 시도]를 키보드로 실행한다. 404 경우 [목록으로]를 실행한다
- 확인:
  - 대기·실패·없는 제안 상태를 구분하고 진행 중 비어 있는 카드를 정상 내용처럼 보이지 않는다
  - 500 후 같은 제안의 전체 내용·사용자·제출일시로 복구하며 URL과 제목이 일치한다
  - 재시도 완료 후 사라진 버튼에 초점이 방치되지 않고 본문 읽기를 이어갈 수 있다
  - 404는 S-제안-017대로 목록으로 이동하며 실패 안내가 다른 조작을 가리지 않는다

### S-제안-023. 좁은 화면·키보드에서도 긴 내용을 끝까지 읽는다

- 실행: E2E
- 로그인: 조회자
- 데이터: `제안-기본`, 페이지 확인은 `제안-25건`
- 창(경우마다 따로): 1440px / 1200px / 1199px / 390px
- 시작: 아이디어 제안 목록
- 행동: 키보드로 검색·유형·정렬·페이지·상세 진입·목록 복귀를 조작하고 #350 전체 내용을 읽는다
- 확인:
  - 초점이 보이고 필터·정렬·페이지·복귀 동작에 접근 가능하며 잘림·가림이 없다
  - 표의 필요한 열은 가로 스크롤로 접근 가능하고 화면 전체에 불필요한 가로 넘침이 없다
  - 상세 한 열 전환 시 500자 본문과 줄바꿈·사용자 정보가 읽히며 긴 문자열이 카드 밖으로 넘치지 않는다
  - 조회 전용이므로 저장·담당 변경·확인 모달·중복 변경 요청 검증은 해당 없음이다
