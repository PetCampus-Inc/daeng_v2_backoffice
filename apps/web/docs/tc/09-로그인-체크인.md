# 09. 로그인·체크인

범위: 3.1 로그인 흐름, 7.1 로그인, 4.5 세션 만료, 6.7 접속 기록, 7.16 팀 체크인.

로그인 연결 방식은 B안이다(OQ-D4): 프론트가 구글 로그인 창(구글이 정한 모양의 버튼)을 띄우고, 구글이 준 토큰을 서버에
보내면 서버가 확인한다. 이 방식은 구글 창을 닫거나 취소한 것을 알 수 없어 '인증 취소'는 처리하지 않는다. E2E는 구글
단계를 건너뛰고 가짜 API의 '로그인 결과'로 시작한다. 실제 구글 로그인은 수동 TC다.

---

## R-로그인판정. 로그인 결과 (7.1, FR-BO-010, 011, 014)

판정: 서버. 입력: 구글이 확인한 이메일. 기대값: 로그인 결과, 화면, 접속 기록 실패 사유. 계정은 `팀원-기본`.

| ID              | 구글이 확인한 이메일     | 로그인 결과 | 화면                                                               | 접속 기록 실패 사유 |
| --------------- | ------------------------ | ----------- | ------------------------------------------------------------------ | ------------------- |
| R-로그인판정-01 | `ops@knockdog.test`      | 성공        | 역할에 허용된 메뉴                                                 | —                   |
| R-로그인판정-02 | `OPS@knockdog.test`      | 성공        | 역할에 허용된 메뉴                                                 | —                   |
| R-로그인판정-03 | `new@knockdog.test`      | 성공        | 첫 로그인 프로필 설정(상태 '활성'으로)                             | —                   |
| R-로그인판정-04 | `stranger@gmail.com`     | 실패        | 빨간 박스 `접근 권한이 없는 계정입니다. 관리자에게 문의해 주세요.` | 미등록              |
| R-로그인판정-05 | `inactive@knockdog.test` | 실패        | 빨간 박스 `접근 권한이 없는 계정입니다. 관리자에게 문의해 주세요.` | 비활성              |
| R-로그인판정-06 | `canceled@knockdog.test` | 실패        | 빨간 박스 `접근 권한이 없는 계정입니다. 관리자에게 문의해 주세요.` | 비활성              |
| R-로그인판정-07 | (구글 창에서 취소)       | 없음        | 로그인 화면 그대로, 안내 없음                                      | (기록하지 않음)     |

- 등록되지 않은 계정으로 로그인해도 계정을 자동으로 만들지 않는다.
- 등록 취소 계정의 실패 사유는 PRD 7.1대로 '비활성'이다.

## R-세션. 로그인 유지 (4.5, FR-BO-012)

판정: 서버. 입력: 마지막 요청 뒤 지난 시간. 기대값: 다음 요청 결과.

| ID        | 마지막 요청 뒤 지난 시간 | 다음 요청 결과 |
| --------- | ------------------------ | -------------- |
| R-세션-01 | 23시간 59분              | 유지           |
| R-세션-02 | 24시간                   | 만료           |
| R-세션-03 | 24시간 1분               | 만료           |

- 최대 유지 기간은 없다. 24시간 안에 계속 요청하면 며칠이 지나도 유지된다.
- '24시간 뒤'를 24시간 0분부터 만료로 봤다. 정확한 경계는 서버 구현과 맞춘다.

## R-접속기록. 접속 기록 (6.7, FR-BO-042)

판정: 서버. 입력: 일어난 일. 기대값: 이벤트 종류, 결과, 이메일.

| ID            | 일어난 일                      | 이벤트 종류         | 결과            | 이메일                   |
| ------------- | ------------------------------ | ------------------- | --------------- | ------------------------ |
| R-접속기록-01 | `운영자` 로그인                | 로그인 성공         | 성공            | `ops@knockdog.test`      |
| R-접속기록-02 | `미등록` 로그인                | 로그인 실패         | 실패: 미등록    | `stranger@gmail.com`     |
| R-접속기록-03 | `비활성팀원` 로그인            | 로그인 실패         | 실패: 비활성    | `inactive@knockdog.test` |
| R-접속기록-04 | `등록취소팀원` 로그인          | 로그인 실패         | 실패: 비활성    | `canceled@knockdog.test` |
| R-접속기록-05 | 구글 창에서 취소(이메일 모름)  | (기록하지 않음)     | —               | —                        |
| R-접속기록-06 | `운영자` 로그아웃              | 로그아웃            | 성공            | `ops@knockdog.test`      |
| R-접속기록-07 | `운영자` 24시간 뒤 요청        | 세션 만료           | 성공            | `ops@knockdog.test`      |
| R-접속기록-08 | `운영자`가 변경 이력 주소 접근 | 권한 없는 접근 시도 | 실패: 권한 없음 | `ops@knockdog.test`      |

- 세션 만료의 '결과' 값은 PRD에 따로 없다. 실패 사유 목록(미등록·비활성·권한 없음)에 없어 '성공'으로 적었다.
- PRD 6.7의 실패 사유 '인증 취소'는 B안에서 서버가 취소를 알 수 없어 기록하지 않는다(OQ-D4).
- 접속 기록은 추가만 되고 보존 기간 제한이 없다. 변경 이력 화면에는 나오지 않는다.

## 로그인 화면 (7.1)

### S-로그인-001. 로그인 화면을 연다 (FR-BO-010)

- 실행: 브라우저 확인
- 로그인: 없음
- 시작: `/home`
- 행동: 화면을 연다
- 확인:
  - 로그인 화면으로 바뀐다
  - 가운데 한 덩어리: 똑독 로고 + `BO` → [Google 계정으로 로그인](구글이 그리는 버튼, 흰 배경 `outline`) → 회색
    `등록된 팀원 계정만 로그인할 수 있습니다.`
  - 안내 박스가 없다
  - 사이드바·상단바가 없다
  - 브라우저 탭 제목이 `… · 똑독 BO` 형식

### S-로그인-002. 로그인하지 않고 BO 화면에 들어가면 로그인 화면이다 (FR-BO-010)

- 실행: E2E
- 로그인: 없음
- 데이터: `문의-기본`
- 시작(경우마다 따로):
  - `/home`
  - 1:1 문의 목록
  - 문의 상세(#1043)
- 행동: 화면을 연다
- 확인:
  - 로그인 화면이 뜨고 BO 데이터가 보이지 않는다

### S-로그인-003. 로그인에 성공한다 (FR-BO-010, 011)

- 실행: E2E
- 로그인: 없음
- API(경우마다 따로): 로그인 결과가 R-로그인판정 표의 '성공' 줄(구글 이메일 `ops@knockdog.test` 또는
  `OPS@knockdog.test`)
- 시작: 로그인 화면
- 행동: [Google 계정으로 로그인] 클릭
- 확인:
  - 역할에 허용된 메뉴가 보이는 BO 화면(`/home`)
  - 사이드바에 '1:1 문의'가 있고 '변경 이력'·'설정'이 없다
  - 상단바 프로필 `김운영 · PM`

### S-로그인-004. 로그인에 실패한다 (FR-BO-011, 014)

- 실행: E2E
- 로그인: 없음
- API(경우마다 따로): 로그인 결과가 미등록 / 비활성 / 등록 취소 실패
- 시작: 로그인 화면
- 행동: [Google 계정으로 로그인] 클릭
- 확인:
  - 로그인 화면에 빨간 박스 `접근 권한이 없는 계정입니다. 관리자에게 문의해 주세요.`
  - BO 메뉴로 들어가지 않는다

### S-로그인-005. 이미 로그인돼 있으면 바로 메뉴가 보인다 (3.1)

- 실행: E2E
- 로그인: 운영자
- 시작: `/home`
- 행동: 새 탭에서 `/home`을 연다
- 확인:
  - 로그인 화면 없이 `/home`

### S-로그인-006. 세션이 만료된 뒤 로그인 화면 (FR-BO-012)

- 실행: E2E
- 로그인: 운영자
- 시각: 마지막 요청 2026. 10. 07. 10:00 → 지금 2026. 10. 08. 10:01
- API: 다음 요청이 세션 만료 응답
- 시작: `/home`
- 행동: 사이드바 '아이디어 제안' 클릭
- 확인:
  - 로그인 화면, 파란 박스 `로그인이 만료되었습니다. 다시 로그인해 주세요.`
  - 이어서 [Google 계정으로 로그인](로그인 결과 성공) → `/home`, 파란 박스 사라짐

### S-로그인-007. 로그아웃한 뒤 BO 주소를 연다 (FR-BO-013)

- 실행: E2E
- 로그인: 운영자
- 시작: `/home`
- 준비: 프로필 패널 [로그아웃] → 로그인 화면
- 행동: 주소 `/home`을 직접 입력
- 확인:
  - 로그인 화면(BO 화면이 열리지 않는다)

### S-로그인-008. 비활성화된 계정의 다음 요청 (FR-BO-014)

- 실행: E2E
- 로그인: 운영자
- API: 다음 요청이 '계정 비활성' 응답(그 사이 비활성화되어 서버가 세션을 지우고, 비활성화 때문에 지웠다고 알려 줌)
- 시작: `/home`
- 행동: 사이드바 '아이디어 제안' 클릭
- 확인:
  - 로그인 화면, 빨간 박스 `접근 권한이 없는 계정입니다. 관리자에게 문의해 주세요.`
  - 이어서 로그인하면(로그인 결과 비활성 실패) 같은 빨간 박스

### S-로그인-009. 실제 구글 계정으로 로그인한다 (FR-BO-010) (연동 대기: OQ-D4)

- 실행: 수동 (실제 구글 로그인)
- 로그인: 없음
- 시작: 개발 서버 BO 로그인 화면
- 행동(경우마다 따로): 등록된 활성 계정 / 등록되지 않은 계정 / 비활성 계정 / 구글 창에서 취소
- 확인:
  - 구글 로그인 창에서 계정을 고르면 BO 화면에서 R-로그인판정 표대로 된다(구글 창에서 취소하면 로그인 화면 그대로)
  - 첫 로그인 때 팀원에 구글 `sub`를 저장하고 이후 `sub`로 찾는다
  - 개인 gmail 계정도 구글 로그인 창을 통과하고, 등록된 팀원인지는 서버가 판정한다(R-로그인판정)

### S-로그인-010. 접속 기록이 서버에 남는다 (FR-BO-042)

- 실행: 수동 (서버 확인 — 접속 기록은 화면이 없다)
- 로그인: 없음
- 시작: 개발 서버
- 행동: R-접속기록 표의 일을 실제로 일으킨다
- 확인:
  - 서버 저장소의 접속 기록이 R-접속기록 표와 같다
  - 기록을 고치거나 지울 수 없다

### S-로그인-011. 24시간 무활동이면 실제 세션이 만료된다 (FR-BO-012)

- 실행: 수동 (서버 확인 — 실제 세션 만료 시간)
- 로그인: 운영자
- 시작: 개발 서버 BO
- 행동: 마지막 요청 뒤 24시간 넘게 기다렸다가 요청(또는 서버 시간 조작)
- 확인:
  - 로그인 화면 + 파란 박스 `로그인이 만료되었습니다. 다시 로그인해 주세요.`
  - 24시간 안에 계속 쓰면 며칠이 지나도 유지된다

## 팀 체크인 (7.16)

### S-로그인-012. 팀 체크인 메뉴로 기존 체크인 화면에 간다 (FR-BO-110)

- 실행: E2E
- 로그인: 조회자
- 시작: `/home`
- 행동: 사이드바 '팀 운영 > 팀 체크인' 클릭
- 확인:
  - 기존 체크인 화면 주소로 이동한다
  - BO 사이드바·상단바(알림·프로필)가 없다

### S-로그인-013. 로그인하지 않아도 체크인 화면이 열린다 (FR-BO-015)

- 실행: E2E
- 로그인: 없음
- 시작: 기존 체크인 화면 주소
- 행동: 화면을 연다
- 확인:
  - 로그인 화면 없이 체크인 화면이 열린다

### S-로그인-014. 체크인 화면이 기존과 같다 (FR-BO-111, 7.16)

- 실행: 수동 (기존 화면 회귀 — 기준이 이전 체크인 화면이다)
- 로그인: 없음
- 시작: 기존 체크인 화면
- 행동: 이름 선택·데이터 입력·팀원 관리를 기존처럼 써 본다
- 확인:
  - 동작·배지·카드 구성·문구·'Blockers'가 기존 그대로다

## 사용성 검증 (2026-10-22)

근거: 사용자 요청에 따른 전체 TC 누락 점검 및
[웹 테스트 가이드](../testing-guide.md#화면-작업의-사용성-검증과-완료-기준). 기존 기능 TC를 보완하는 조작 품질 기준이다.
PRD OQ 결정 대기 항목의 기대값이나 새로운 PRD 기능을 확정하지 않는다. 실행 조건에 별도 표시가 없으면 정상 응답과 1.5초
지연 응답을 각각 적용하고 첫 방문·재방문을 따로 확인한다. 자동 판정은 E2E로, 깜빡임·배치의 지각적 품질은 전환 중
DOM·위치·포커스·스크롤 관찰과 trace를 함께 보고 판단한다. TC 작성은 검증 통과를 뜻하지 않는다. 실행 결과·항목별
판정·관찰 자료는 Git에서 제외된 로컬 검증 결과 폴더에 남긴다.

적용 범위: 로그인 응답·세션 복구·로그아웃·체크인 진입. 구글 창 취소를 감지하지 않는 B안 정책을 유지한다. 실제 구글
인증과 기존 체크인 비교는 수동 TC이며, 가짜 인증 결과로 해당 동작을 검증 완료했다고 보고하지 않는다.

### S-로그인-015. 로그인 응답 지연·실패 후 다시 조작할 수 있다

- 실행: E2E
- 로그인: 없음
- API: 구글 인증 후 BO 로그인 결과 1.5초 지연 후 성공 / 접근 거부 / 500 후 정상(경우마다 따로)
- 시작: 로그인 화면
- 준비: E2E는 기존 정의대로 구글 단계를 대체하고 서버 로그인 결과만 제어한다
- 행동: 로그인을 연속 실행하고 실패 후 다시 시도한다
- 확인:
  - 인증 결과 처리 중임을 알 수 있고 중복 로그인 처리·중복 화면 이동을 막는다
  - 실패 시 로그인 조작을 다시 실행할 수 있으며 오류 박스가 버튼을 가리거나 초점을 잃게 하지 않는다
  - 성공 후 역할·프로필 설정 여부와 목적 화면이 일치하고 오류 안내가 남지 않는다
  - 구글 창 취소 안내나 취소 감지를 새로운 기능으로 요구하지 않는다

### S-로그인-016. 세션 확인·재로그인·계정 전환 중 화면이 섞이지 않는다

- 실행: E2E
- 로그인: 운영자
- 데이터: `문의-기본`
- API: 세션 판정 또는 로그인 결과 1.5초 지연, 별도 경우 기존 요청이 로그아웃 뒤 늦게 도착
- 시작: 문의 상세(#1043)
- 준비: 기존 S-로그인-006의 세션 만료 또는 로그아웃 조건을 만든다(경우마다 따로)
- 행동: 로그인 화면에서 다른 역할 계정으로 로그인한다
- 확인:
  - 세션 판정 중 로그인·BO 화면이 불필요하게 번갈아 점멸하지 않는다
  - 늦은 응답이 이전 계정의 메뉴·프로필·데이터를 다시 노출하지 않는다
  - 만료·접근 거부 안내와 새 계정의 메뉴·이동 결과가 일치하고 성공 후 이전 안내는 사라진다
  - 키보드 초점이 제거된 로그인 버튼에 방치되지 않고 새 화면을 사용할 수 있다
  - 만료 시 초안 제거·재로그인 목적지는 기존 기능 TC 정책을 따른다

### S-로그인-017. 좁은 화면·키보드로 로그인과 체크인 진입을 조작한다

- 실행: E2E
- 로그인: 없음
- 창(경우마다 따로): 1440px / 390px
- 시작: 로그인 화면
- API: E2E 로그인 결과는 조회자 성공
- 행동: 키보드로 로그인한 뒤 팀 체크인 메뉴를 실행한다
- 확인:
  - 로그인 버튼·오류 안내·메뉴에 접근 가능하며 초점 표시와 문구가 가려지지 않는다
  - 이동 중 진행을 알 수 있고 체크인 화면에 BO 사이드바·상단바가 겹쳐 남지 않는다
  - 체크인 진입 후 조작할 위치로 초점이 이어지고 예상하지 않은 전체 가로 넘침이 없다
  - 실제 구글 제공 버튼의 키보드 조작은 S-로그인-009의 외부 연동 완료 후 별도 확인한다

### S-로그인-018. 기존 체크인 입력·저장·복구의 조작 품질을 비교한다

- 실행: 수동 (기존 체크인 화면 회귀 — 기존 화면과 연결 환경이 필요하다)
- 로그인: 없음
- 시작: 기존 체크인 화면
- 준비: 비교용 입력을 정하고 정상 응답 / 연결 환경에서 가능한 1~3초 지연·실패 조건을 각각 만든다
- 행동: 이름 선택·데이터 입력·팀원 관리의 기존 저장 동작을 실행하고 실패하면 기존 복구 동작을 사용한다
- 확인:
  - 입력 반응·커서·포커스·스크롤이 조작 도중 뜻밖에 초기화되지 않는다
  - 대기 이유·성공·실패를 구별하고 저장 중 중복 실행으로 결과가 중복되지 않는다
  - 실패 시 기존 복구 경로로 재시도하거나 취소할 수 있고 입력을 불필요하게 잃지 않는다
  - 좁은 화면·키보드로 기존 주요 조작에 접근하고 카드·안내가 불필요하게 튀거나 가려지지 않는다
  - 기존 환경이 없거나 지연·실패를 만들 수 없는 경우 해당 조건을 미확인으로 기록한다

### F-로그인-01. 로그인해 역할에 맞는 메뉴를 쓰고 로그아웃한다 (3.1)

- 로그인: 없음

1. `/home` 접속 → 로그인 화면
2. [Google 계정으로 로그인](로그인 결과 `조회자` 성공) → `/home`, 사이드바에 '1:1 문의'·'변경 이력'·'설정'이 없다
3. 1:1 문의 목록 주소 직접 입력 → 권한 없음 화면
4. [홈으로 이동] → `/home`
5. 프로필 패널 [로그아웃] → 로그인 화면, 브라우저 뒤로 → 로그인 화면

### F-로그인-02. 세션이 만료되면 다시 로그인한다 (3.1, FR-BO-012)

- 로그인: 운영자 / 데이터: `문의-기본`

1. 문의 상세(#1043)에서 답변 `확인해 보겠습니다` 입력
2. 시각을 25시간 뒤로 옮기고 (가짜 API) 다음 요청을 세션 만료로 → [답변 저장] → 확인창 없이 로그인 화면, 파란 박스
   `로그인이 만료되었습니다. 다시 로그인해 주세요.`
3. 다시 로그인 → `/home`
4. 문의 상세(#1043) → 답변 입력칸이 비어 있고 운영자 메시지가 늘지 않았다
