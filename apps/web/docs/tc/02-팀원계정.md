| ID            | 현재 상태 | 로그인 이력 | 일어난 일 | 다음 상태 |
| ------------- | --------- | ----------- | --------- | --------- |
| R-팀원상태-01 | (없음)    | 없음        | 등록      | 등록됨    |
| R-팀원상태-02 | 등록됨    | 없음        | 첫 로그인 | 활성      |
| R-팀원상태-03 | 등록됨    | 없음        | 등록 취소 | 등록 취소 |
| R-팀원상태-04 | 활성      | 있음        | 비활성화  | 비활성    |
| R-팀원상태-05 | 비활성    | 있음        | 재활성화  | 활성      |
| R-팀원상태-06 | 비활성    | 없음        | 재활성화  | 등록됨    |
| R-팀원상태-07 | 등록 취소 | 없음        | 재활성화  | 등록됨    |

| R-팀원메뉴-02 | 등록됨    | 아니오  | `역할 변경` · `등록 취소`(빨강) |

## R-팀원보호. 마지막 최고 관리자·본인 보호 (FR-BO-024)

판정: 서버(화면도 같은 판정으로 메뉴 항목을 막는다). 입력: 대상, 대상 역할·상태, 대상 말고 다른 활성 최고 관리자 수.
기대값: 역할 변경·비활성화.

| ID            | 대상      | 대상 역할·상태     | 다른 활성 최고 관리자 수 | 역할 변경·비활성화 |
| ------------- | --------- | ------------------ | ------------------------ | ------------------ |
| R-팀원보호-01 | 본인      | 최고 관리자·활성   | 1                        | 불가               |
| R-팀원보호-02 | 다른 팀원 | 최고 관리자·활성   | 0                        | 불가               |
| R-팀원보호-03 | 다른 팀원 | 최고 관리자·활성   | 1                        | 가능               |
| R-팀원보호-04 | 다른 팀원 | 최고 관리자·등록됨 | 1                        | 가능               |
| R-팀원보호-05 | 다른 팀원 | 운영자·활성        | 1                        | 가능               |
| R-팀원보호-06 | 다른 팀원 | 조회자·활성        | 1                        | 가능               |

- '마지막'은 활성 최고 관리자만 센다('등록됨' 제외). 불가면 메뉴 항목 비활성 +
  `마지막 최고 관리자와 본인 계정은 변경할 수 없습니다.`
- 보는 사람은 늘 활성 최고 관리자이므로, '다른 활성 최고 관리자 수 0'인 행은 정상 화면에서는 생기지 않는다(본인 행은 ⋯가
  없음). 동시에 서로를 바꾸는 경합에서 서버가 이 판정으로 거부한다.

## 팀원 목록 (7.13)

### S-팀원-001. 팀원·권한 화면을 연다 (FR-BO-020)

- 실행: 브라우저 확인
- 로그인: 최고관리자
- 시작: 설정 > 팀원·권한
- 행동: 화면을 연다
- 확인:
  - 머리 오른쪽 [팀원 등록]
  - 표 열: 팀원 | 상태 | 역할 | 직무 | 마지막 로그인 | 등록일 | ⋯
  - 팀원 칸: 표시명, 아래 줄 이메일. `new@knockdog.test`·`canceled@knockdog.test` 행은 `이름 없음`, 직무 비어 있음
  - 상태 배지: 등록됨 파랑 / 활성 초록 / 비활성·등록 취소 회색
  - 로그인 이력이 없는 행은 마지막 로그인이 비어 있다
  - 마지막 로그인·등록일 `2026. 10. 06. 09:00` 형식
  - 비활성·등록 취소 계정도 목록에 있다(7행)
  - 검색·필터 줄과 `총 N건`이 없다
  - 사이드바 '팀원·권한' 강조, 브레드크럼 없음

### S-팀원-002. 행마다 ⋯ 메뉴를 연다 (FR-BO-022, 023)

- 실행: E2E
- 로그인: 최고관리자
- 시작: 설정 > 팀원·권한
- 행동(경우마다 따로):
  - `ops@knockdog.test` 행 ⋯ → `역할 변경` · `비활성화`
  - `new@knockdog.test` 행 ⋯ → `역할 변경` · `등록 취소`
  - `inactive@knockdog.test` 행 ⋯ → `재활성화`
  - `canceled@knockdog.test` 행 ⋯ → `재활성화`
  - `admin@knockdog.test`(본인) 행 → ⋯ 버튼이 없다
- 확인:
  - 경우별 메뉴 항목

### S-팀원-003. 팀원 목록을 불러오는 중 (4.5)

- 실행: E2E
- 로그인: 최고관리자
- API: 팀원 목록 요청이 3초 늦게 응답
- 시작: 설정 > 팀원·권한
- 행동: 화면을 연다
- 확인:
  - 표 자리에 회색 막대 3줄

### S-팀원-004. 팀원 목록 조회가 실패한다 (4.5)

- 실행: E2E
- 로그인: 최고관리자
- API: 팀원 목록 요청이 500 응답
- 시작: 설정 > 팀원·권한
- 행동: 화면을 연다
- 확인:
  - 표 자리 가운데 `데이터를 불러오지 못했습니다.` / `잠시 후 다시 시도해 주세요.` + [다시 시도]
  - (API를 정상으로 돌린 뒤) [다시 시도] 클릭 → 7행이 보인다

### S-팀원-005. 최고 관리자가 아니면 들어갈 수 없다 (4.1)

- 실행: E2E
- 로그인: 운영자
- 시작: 설정 > 팀원·권한(주소 직접 입력)
- 행동: 화면을 연다
- 확인:
  - 권한 없음 화면 `접근 권한이 없습니다.` + [홈으로 이동]
  - 팀원 목록 요청 결과가 화면에 보이지 않는다

## 팀원 등록 창 (7.13, FR-BO-021)

### S-팀원-006. 팀원 등록 창을 연다

- 실행: 브라우저 확인
- 로그인: 최고관리자
- 시작: 설정 > 팀원·권한
- 행동: [팀원 등록] 클릭
- 확인:
  - 창 제목 `팀원 등록`
  - 순서: 구글 이메일 → 역할(최고 관리자 / 운영자 / 조회자) → 회색
    `안내 메일은 보내지 않습니다. 등록한 분께 직접 알려 주세요.` → [취소][등록]
  - 표시명·직무 입력칸이 없다

### S-팀원-007. 새 팀원을 등록한다

- 실행: E2E
- 로그인: 최고관리자
- 시작: 설정 > 팀원·권한
- 준비: [팀원 등록] → 이메일 `new2@example.com`, 역할 운영자
- 행동: [등록] 클릭
- 확인:
  - 확인창 없이 창이 닫힌다
  - 토스트 `new2@example.com 계정을 등록했습니다.`
  - 목록에 `이름 없음` / `new2@example.com` 행, 상태 '등록됨', 역할 운영자, 직무 비어 있음

### S-팀원-008. 등록할 수 없는 이메일을 넣는다

- 실행: E2E
- 로그인: 최고관리자
- 시작: 설정 > 팀원·권한
- 준비: [팀원 등록] → 역할 운영자
- 행동(경우마다 따로): 이메일 입력 후 [등록]
  - `abc` → `올바른 이메일 주소를 입력해 주세요.`
  - `OPS@Knockdog.Test` → `이미 등록된 이메일입니다.`
  - `new@knockdog.test` → `이미 등록된 이메일입니다.`
  - `inactive@knockdog.test` → `비활성·등록 취소 계정은 재활성화로만 되돌릴 수 있습니다.`
  - `canceled@knockdog.test` → `비활성·등록 취소 계정은 재활성화로만 되돌릴 수 있습니다.`
- 확인:
  - 창이 닫히지 않고 이메일 칸 아래에 경우별 문구
  - 입력한 이메일이 그대로 남는다
  - 목록에 행이 늘지 않는다

### S-팀원-009. [등록] 요청 중에는 다시 누를 수 없다

- 실행: E2E
- 로그인: 최고관리자
- API: 팀원 등록 요청이 2초 늦게 응답
- 시작: 설정 > 팀원·권한
- 준비: [팀원 등록] → 이메일 `new2@example.com`
- 행동: [등록]을 빠르게 두 번 클릭
- 확인:
  - 응답 전까지 [등록] 비활성
  - 등록 요청이 한 번만 간다

### S-팀원-010. 등록이 실패한다

- 실행: E2E

### S-팀원-011. 이메일을 입력한 채 등록 창을 닫으려 한다 (4.6)

## 사용성 검증 (2026-10-22)

근거: 사용자 요청에 따른 전체 TC 누락 점검 및
[웹 테스트 가이드](../testing-guide.md#화면-작업의-사용성-검증과-완료-기준). 기존 기능 TC를 보완하는 조작 품질 기준이다.
PRD OQ 결정 대기 항목의 기대값이나 새로운 PRD 기능을 확정하지 않는다. 실행 조건에 별도 표시가 없으면 정상 응답과 1.5초
지연 응답을 각각 적용하고 첫 방문·재방문을 따로 확인한다. 자동 판정은 E2E로, 깜빡임·배치의 지각적 품질은 전환 중
DOM·위치·포커스·스크롤 관찰과 trace를 함께 보고 판단한다. TC 작성은 검증 통과를 뜻하지 않는다. 실행 결과·항목별
판정·관찰 자료는 Git에서 제외된 로컬 검증 결과 폴더에 남긴다.

적용 범위: 목록·등록·역할 변경·계정 상태 변경. 검색·필터·페이지는 정의된 화면에 없으므로 해당 없음.
