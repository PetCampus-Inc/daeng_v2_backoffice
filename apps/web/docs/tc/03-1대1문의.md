## 문의 목록 (7.3)

### S-문의-001. 문의 목록을 연다 (FR-BO-050, 051)

- 실행: 브라우저 확인
- 로그인: 운영자
- 데이터: `문의-기본`
- 시작: 1:1 문의 목록
- 행동: 화면을 연다
- 확인:
  - 툴바 순서: 검색(안내 글자 `제목, 사용자, 문의 번호, 대화 내용`) → 상태 → 사용자 유형 → 담당자 → 오른쪽 끝 `총 10건`
  - `필터 초기화`가 없다
  - 표 열: 문의 번호 | 상태 | 제목 | 사용자 | 담당자 | 최근 활동 ↓
  - 사용자 칸 `보호자 · 홍길동` 형식
  - 담당자 칸 `김운영 · PM`, #1047은 `정비활 · BE` 뒤 회색 `(비활성)`, 미배정은 회색 `미배정`
  - 상태 배지: 답변 대기 노랑 / 확인 중 파랑 / 답변 도착 초록 / 해결 완료 회색
  - 최근 활동 `2026. 10. 07. 09:30` 형식
  - 브레드크럼 없음, 사이드바 '1:1 문의' 강조

- 확인:
  - 저장 진행 상태를 알 수 있고 같은 답변이 중복 요청·대화로 추가되지 않는다
  - 처리 중 안내가 보이고 답변 입력은 잠시 읽기 전용이다. 대기 중 입력 시도로 저장 이후 글이 소실되지 않는다
  - 실패 시 입력·글자 수·초점·스크롤·미저장 상태를 유지하며 재시도할 수 있다
  - 성공 시 요청한 답변만 대화에 한 번 추가되고 상태·입력·저장 버튼이 일치한다
  - 성공·실패 안내나 글자 수 오류 표시가 입력 위치를 갑자기 밀거나 조작을 가리지 않는다

### S-문의-075. 담당 변경·해제·실행 취소와 경합 후 조작이 이어진다

- 실행: E2E
- 로그인: 운영자
- 데이터: `문의-기본`
- API: 맡기·담당 해제·실행 취소 각 1.5초 지연, 별도 경우 500·담당자 변경·해결 완료 거부
- 시작: 문의 상세(#1041) 또는 내 담당 문의(#1043)
- 준비: 기존 S-문의-035~046, 053~054의 경합·거부 조건을 경우마다 적용한다
- 행동: 해당 담당 변경 동작을 연속 실행하거나 실패 후 재시도한다
- 확인:
  - 요청 중 중복·충돌 동작을 막고 진행 상태를 알 수 있다
  - 대기·완료 후 담당자·상태·답변 권한·버튼이 일치하며 실패를 성공처럼 표시하지 않는다
  - 담당 해제 성공 시에만 초안을 비우고 실패하면 보존한다
  - 담당자 변경 거부 시 기존 TC대로 답변 복사·이탈 경고가 가능하고, 해결 완료 거부는 기존 정책대로 입력을 비운다
  - 실행 취소 토스트와 버튼은 키보드로 접근 가능하고, 처리 후 사라진 버튼에 초점이 방치되지 않는다

### S-문의-076. 좁은 화면과 키보드에서도 목록·대화·답변을 조작한다

- 실행: E2E
- 로그인: 운영자
- 데이터: `문의-기본`, 페이지 확인은 `문의-25건`
- 창(경우마다 따로): 1440px / 1200px / 1199px / 390px
- 시작: 1:1 문의 목록
- 행동: 키보드로 검색·모든 필터·정렬·페이지·상세 진입·답변 입력·확인창 취소를 순서대로 조작한다
- 확인:
  - 초점 표시가 보이고 입력·버튼·드롭다운·확인창이 화면 밖으로 잘리거나 서로 가리지 않는다
  - 표의 필요한 열은 가로 스크롤로 접근 가능하고 화면 전체의 불필요한 가로 넘침이 없다
  - 상세 한 열 전환 시 긴 제목·긴 대화·첨부·사용자 정보·답변과 저장 버튼을 읽고 조작할 수 있다
  - 500자 경계·오류 안내가 생겨도 글자 수·저장 가능 상태가 일치하고 입력 포커스를 잃지 않는다
