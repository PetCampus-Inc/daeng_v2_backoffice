## R-알림대상. 알림 받는 사람 (8장, FR-BO-101, 060)

판정: 서버. 입력: 일어난 일, 조건. 기대값: BO 알림 받는 사람, 디스코드. 계정은 `팀원-기본` 기준.

| ID            | 일어난 일             | 조건                                  | BO 알림 받는 사람                           | 디스코드 |
| ------------- | --------------------- | ------------------------------------- | ------------------------------------------- | -------- |
| R-알림대상-01 | 새 1:1 문의 접수      | —                                     | `최고관리자`, `운영자`, `운영자2`           | 보냄     |
| R-알림대상-02 | 사용자 추가 문의      | 담당자 `운영자`(활성), 상태 답변 대기 | `운영자`                                    | 보냄     |
| R-알림대상-03 | 사용자 추가 문의      | 담당자 `운영자`(활성), 상태 확인 중   | `운영자`                                    | 보냄     |
| R-알림대상-04 | 사용자 추가 문의      | 담당자 `운영자`(활성), 상태 답변 도착 | `운영자`                                    | 보냄     |
| R-알림대상-05 | 사용자 추가 문의      | 미배정                                | (없음)                                      | 보냄     |
| R-알림대상-06 | 사용자 추가 문의      | 담당자 `비활성팀원`                   | (없음)                                      | 보냄     |
| R-알림대상-07 | 문의 담당자 변경      | 이전 담당자 `운영자2`(활성)           | `운영자2`                                   | 안 보냄  |
| R-알림대상-08 | 문의 담당자 변경      | 이전 담당자 `비활성팀원`              | (없음)                                      | 안 보냄  |
| R-알림대상-09 | 미배정 문의 맡기      | —                                     | (없음)                                      | 안 보냄  |
| R-알림대상-10 | 새 아이디어 제안 접수 | —                                     | `최고관리자`, `운영자`, `운영자2`, `조회자` | 안 보냄  |
| R-알림대상-11 | 리뷰 신고 접수        | —                                     | (없음)                                      | —        |

- 받는 사람은 일이 생긴 시점의 활성 계정이다. '등록됨'·'등록 취소'·'비활성' 계정에는 만들지 않는다.
- 같은 문의에 추가 문의가 두 번 오면 알림도 두 번 생긴다.
- 이미 생긴 알림은 받은 사람의 역할이 바뀌어도 남는다. 비활성이었다가 재활성화돼도 비활성 동안의 알림은 생기지 않는다.
- 리뷰 신고는 앱이 접수할 때 디스코드로 보내므로 BO 알림이 없다.

## 알림 센터 (7.14)

### S-알림-001. 알림 팝오버를 연다 (FR-BO-100)

- 실행: 브라우저 확인
- 로그인: 운영자
- 데이터: `알림-기본`, `문의-기본`, `제안-기본`
- 시작: `/home`
- 행동: 상단바 알림 아이콘 클릭
- 확인:
  - 아이콘 숫자 `3`
  - 아래로 폭 380의 팝오버
  - 머리 `알림` + 오른쪽 `모두 읽음`
  - 최근순 4건(`fixtures.md` 순서), 항목 = 주황 점(안 읽음) · 문구 한 줄 · 시각
  - 2번(담당자 변경)은 점 없이 회색
  - 시각은 KST 공통 형식

### S-알림-002. 문의 알림을 누른다 (FR-BO-100)

- 실행: E2E
- 로그인: 운영자
- 데이터: `알림-기본`, `문의-기본`, `제안-기본`
- 시작: `/home`
- 준비: 알림 팝오버를 연다
- 행동(경우마다 따로):
  - 1번 `새 1:1 문의가 등록되었습니다. 문의 #1041` → 문의 상세(#1041)
  - 4번 `담당 중인 문의에 추가 문의가 왔습니다. 문의 #1050` → 문의 상세(#1050)
  - 3번 `새 아이디어 제안이 등록되었습니다. 제안 #350` → 제안 상세(#350)
  - 2번(이미 읽음) → 문의 상세(#1045), 숫자 `3` 그대로
- 확인:
  - 경우별 상세로 이동한다
  - 다시 팝오버를 열면 누른 항목이 읽음(점 없음·회색), 안 읽은 항목을 눌렀으면 아이콘 숫자 `2`

### S-알림-003. 볼 수 없는 대상의 알림을 누른다 (7.14)

### S-알림-006. 읽음은 사람마다 따로다 (8장)

### S-알림-008. 작성 중에 알림을 눌러 [나가기]를 고른다 (7.14, 4.6)

- 확인:

## 알림 생성 (8장)

### S-알림-009. 새 문의가 오면 알림이 생긴다 (8장)

- 실행: E2E
- 로그인: 운영자
- 데이터: `문의-기본`
- 시작: `/home`
- 행동: (가짜 API) 앱에서 새 문의 #1051 접수 후 화면을 새로 연다
- 확인:
  - 아이콘 숫자 `1`
  - 팝오버 맨 위 `새 1:1 문의가 등록되었습니다. 문의 #1051`(안 읽음)

### S-알림-010. 담당자 변경 알림 문구에 바꾼 사람 이름이 들어간다 (8장)

- 실행: E2E
- 로그인: 운영자2
- 데이터: `문의-기본`
- 시작: `/home`
- 행동: (가짜 API) `운영자`가 #1045를 [내가 맡기] → [담당자 변경] 한 뒤 화면을 새로 연다
- 확인:
  - 팝오버 맨 위 `김운영 · PM님이 문의의 담당자를 변경했습니다.`
  - 누르면 문의 상세(#1045)

### S-알림-011. 서버가 알림 받는 사람을 규칙대로 정한다 (8장)

- 실행: 수동 (서버 확인 — 실제 서버의 알림 생성은 가짜 API로 확인할 수 없다)
- 로그인: 최고관리자, 운영자, 운영자2, 조회자(각각)
- 시작: 실제 개발 서버
- 행동: R-알림대상 표의 일을 앱·BO에서 실제로 일으킨다
- 확인:
  - 각 계정의 알림 센터가 R-알림대상 표의 받는 사람과 같다
  - 역할을 바꿔도 이미 받은 알림이 남는다

### S-알림-012. 디스코드 팀 채널로 알림이 간다 (FR-BO-102)

- 실행: 수동 (디스코드 도착 확인)
- 로그인: 없음
- 시작: 실제 개발 서버, 디스코드 팀 채널
- 행동: 앱에서 새 1:1 문의와 추가 문의를 등록하고, BO에서 담당자를 바꾸고, 앱에서 새 제안을 등록한다
- 확인:
  - 새 문의·추가 문의(미배정 포함)는 팀 채널 하나에 온다
  - 담당자 변경·새 제안은 디스코드로 오지 않는다
  - 개인 멘션이 없다
  - 문구에 사용자 이름·연락처 같은 사용자 정보와 문의 본문이 없다

## 흐름

### F-알림-01. 새 문의 알림을 받아 맡는다 (3.3, 7.14)

- 로그인: 운영자 / 데이터: `문의-기본`

1. (가짜 API) 앱에서 새 문의 #1051 접수 → 새로고침하면 아이콘 숫자 `1`
2. 알림 팝오버 → `새 1:1 문의가 등록되었습니다. 문의 #1051` 클릭 → 문의 상세(#1051), 머리 `미배정` + [내가 맡기]
3. [내가 맡기] → 상태 '확인 중'
4. (가짜 API) 사용자가 #1051에 추가 문의 → 새로고침하면 아이콘 숫자 `1`,
   `담당 중인 문의에 추가 문의가 왔습니다. 문의 #1051`
5. 상태 '답변 대기', 담당자 `김운영 · PM` 그대로

### F-알림-02. 담당을 해제한 문의의 추가 문의는 BO 알림이 없다 (8장)

- 로그인: 운영자 / 데이터: `문의-기본`

1. 문의 상세(#1043)에서 [담당 해제] → 머리 `미배정`
2. (가짜 API) 사용자가 #1043에 추가 문의 → 새로고침해도 알림 아이콘 숫자 없음
3. 1:1 문의 목록 → #1043 상태 '답변 대기', 담당자 `미배정`, 맨 위
