# 13. 원장 인증 현황

범위: 7.16 기존 조회 화면 중 원장 인증 현황, 4.1 권한, 4.2 화면 틀, 4.4 목록 공통, 4.5 화면 상태, 2.2 제외 항목(원장
인증 심사는 4.0 에픽 KD3-567).

7.16은 이 화면을 '개편안 구현 그대로' 둔다고 한다. 그래서 기준은 기존 화면
`daeng_discord/public/service-admin.html`(이하 service-admin.html)의 원장 인증 현황이고, 칸 값의 뜻은 기존 서버 코드
`apps/daeng-admin/service-admin.js`를 따랐다. API는 백엔드가 새로 만든다. 상세는 따로 화면이 아니라 목록 오른쪽
패널이다. 연락처·사업자번호 가리기는 `11-회원.md` R-가림을 쓴다.

---

## R-인증탭. 단계 탭 (7.16, service-admin.html 기준)

입력: 탭, `인증-기본`. 기대값: 결과(제출일 최신순).

| ID          | 탭              | 결과                                   |
| ----------- | --------------- | -------------------------------------- |
| R-인증탭-01 | 전체            | 김신청, 이원장, 박원장, 최해지, 정입력 |
| R-인증탭-02 | 사업자번호 대기 | 김신청                                 |
| R-인증탭-03 | 인증 완료       | 이원장, 박원장                         |
| R-인증탭-04 | 해지됨          | 최해지                                 |

- '유치원 정보 입력' 단계는 탭이 없어 '전체'에서만 보인다(기존 그대로).
- 제출일이 없는 건(정입력)은 맨 뒤에 두고, 그 안에서는 번호 큰 것 먼저(4.4 동률 규칙). 정렬을 '오래된 순'으로 바꿔도 맨
  뒤다. 기존 API는 제출일이 없으면 인증 번호로 정렬 값을 대신해 순서가 일정하지 않았다. 제출일이 실제로 비는지는 백엔드
  확인 전이다(PRD OQ-D5). 답이 오면 이 줄을 다시 본다

## 원장 인증 현황 (7.16)

### S-인증-001. 원장 인증 현황을 연다 (7.16, service-admin.html 기준)

- 실행: 브라우저 확인
- 로그인: 조회자
- 데이터: `인증-기본`
- 시작: 원장 인증 현황
- 행동: 화면을 연다
- 확인:
  - 제목 `원장 인증 현황`, 아래 회색 `자동 사업자 인증과 원장 권한 연결 상태를 조회합니다.`
  - 왼쪽 표 카드, 오른쪽 상세 패널(폭 390px)
  - 표 카드 위쪽 탭: `전체` · `사업자번호 대기` · `인증 완료` · `해지됨`, '전체' 선택(주황 밑줄)
  - 툴바: 검색(안내 글자 `신청자 또는 유치원 검색`) → 정렬 드롭다운(처음 `최신 순`) → 오른쪽 끝 `총 5건` (PRD 4.4)
  - 표 열: 신청자 | 유치원 | 지역 | 신청일 | 단계
  - 행 순서: 김신청, 이원장, 박원장, 최해지, 정입력
  - 상세 패널 가운데 ☝ + 회색 `왼쪽에서 인증 건을 선택해주세요.`
  - 브레드크럼 없음, 사이드바 '고객 관리 > 원장 인증 현황' 강조 (4.2)
  - 브라우저 탭 제목 `원장 인증 현황 · 똑독 BO` (4.2)

  - `대표자 정보`: 대표자 `이원장` / 연락처 `010-****-3333`

### S-인증-008. 상세 패널에 처리 버튼이 없다 (2.2)

- 실행: 브라우저 확인
- 로그인: 최고관리자
- 데이터: `인증-기본`
- 시작: 원장 인증 현황
- 준비: 김신청 행 클릭

  - 패널 안 글자는 모두 읽기만 된다
  - 기존 HTML에 남아 있는 '신청 승인' 창(처리 메모·사용자 알림·[확인])은 만들지 않는다. 여는 경로가 없고, 원장 인증
    심사는 1단계 범위 밖이다(2.2)

### S-인증-009. 검색창에 입력한다 (7.16, 4.4)

- 실행: E2E
- 로그인: 조회자
- 데이터: `인증-기본`
- 시작: 원장 인증 현황
- 행동(경우마다 따로):
  - '전체' 탭에서 `햇살` 입력 → 이원장
  - '전체' 탭에서 `김신청`(앞뒤 공백) 입력 → 김신청
  - '인증 완료' 탭에서 `원장` 입력 → 이원장, 박원장
  - '해지됨' 탭에서 `햇살` 입력 → 검색 결과 없음
- 확인:
  - 입력을 멈추면 [검색] 버튼 없이 표가 경우별 결과로 바뀌고 `총 N건`도 맞는다(유치원 화면 S-유치원-005와 같은 방식)
  - 검색 대상은 유치원명·대표자 이름·회원 ID, 부분 일치, 앞뒤 공백 무시(기존 API 기준, 4.4)
  - 탭을 바꿔도 검색어는 그대로 두고 함께 건다. 검색어를 바꾸면 1페이지로, 상세 패널 선택은 풀린다
  - 조건이 있으면 `필터 초기화`가 보이고, 누르면 검색어·정렬이 처음으로 돌아간다(4.4)
  - 결과가 없으면 표 자리 가운데 `검색 결과가 없습니다.` + [필터 초기화], `총 0건`(PRD 4.5)
  - 기존은 검색창이 있지만 동작하지 않았다. 동작하게 옮긴다(2026-10-22 결정)

### S-인증-010. 정렬 드롭다운을 고른다 (7.16, 4.4)

- 실행: E2E
- 로그인: 조회자
- 데이터: `인증-기본`
- 시작: 원장 인증 현황
- 행동: 정렬 드롭다운에서 `오래된 순`을 고른 뒤 다시 `최신 순`을 고른다
- 확인:
  - 선택지 `최신 순` · `오래된 순`, 처음 값 `최신 순`
  - `오래된 순`: 최해지, 박원장, 이원장, 김신청, 정입력(제출일 없는 건은 맨 뒤, R-인증탭)
  - `최신 순`: 김신청, 이원장, 박원장, 최해지, 정입력
  - 정렬을 바꾸면 1페이지로, 상세 패널 선택은 풀린다
  - 기존은 처음 값이 `오래된 순`이었지만 골라도 순서가 바뀌지 않았고 실제 순서는 늘 최신순이었다. 동작하게 하고 처음
    값을 실제 순서와 같은 `최신 순`으로 했다(2026-10-22 결정). 새 API에 정렬 값이 필요하다

## 사용성 검증 (2026-10-22)

근거: 사용자 요청에 따른 전체 TC 누락 점검 및
[웹 테스트 가이드](../testing-guide.md#화면-작업의-사용성-검증과-완료-기준). 기존 기능 TC를 보완하는 조작 품질 기준이다.
PRD OQ 결정 대기 항목의 기대값이나 새로운 PRD 기능을 확정하지 않는다. 실행 조건에 별도 표시가 없으면 정상 응답과 1.5초
지연 응답을 각각 적용하고 첫 방문·재방문을 따로 확인한다. 자동 판정은 E2E로, 깜빡임·배치의 지각적 품질은 전환 중
DOM·위치·포커스·스크롤 관찰과 trace를 함께 보고 판단한다. TC 작성은 검증 통과를 뜻하지 않는다. 실행 결과·항목별
판정·관찰 자료는 Git에서 제외된 로컬 검증 결과 폴더에 남긴다.

적용 범위: 단계 탭·목록·페이지·행 선택·상세 패널·복구. 조회 전용이므로 승인/반려·저장·초안 이탈은 해당 없음.
검색·정렬·새로고침 후 선택 보존·제출일 없는 건의 정렬은 2026-10-22에 정했다(S-인증-009·010·017, R-인증탭).
