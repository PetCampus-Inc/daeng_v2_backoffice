# 11. 회원

범위: 7.16 기존 조회 화면 중 회원, 4.1 권한, 4.2 화면 틀, 4.4 목록 공통, 4.5 화면 상태, 2.2 제외 항목(목록 내보내기는
KD3-580).

7.16은 이 화면을 '개편안 구현 그대로' 둔다고 한다. 그래서 기준은 기존 화면
`daeng_discord/public/service-admin.html`(이하 service-admin.html)의 회원 관리이고, 칸 값의 뜻은 기존 서버 코드
`apps/daeng-admin/service-admin.js`를 따랐다. API는 백엔드가 새로 만든다. 조회 전용이라 상세 화면이 없다.

- 검색 대상은 이름·이메일·전화번호·회원 ID다. 이메일·전화번호는 화면에서 가린 값이 아니라 원래 값으로 찾는다.
- 부분 일치, 대소문자 무시, 앞뒤 공백 무시(4.4, 기존 API 기준).
- 견주 = 반려견이 1마리 이상(탈퇴 회원도 포함), 원장 = 해지되지 않은 원장 역할이 있음, 탈퇴 = 계정 상태 탈퇴.
- 탭을 바꿔도 검색어는 그대로 두고 함께 건다.

## R-회원유형. 회원 유형·원장 상태 (7.16, service-admin.html 기준)

입력: 반려견 수, 원장 역할. 기대값: 회원 유형, 원장 상태.

| ID            | 반려견 수 | 원장 역할 | 회원 유형     | 원장 상태 |
| ------------- | --------- | --------- | ------------- | --------- |
| R-회원유형-01 | 2         | 없음      | `견주`        | `미보유`  |
| R-회원유형-02 | 1         | 있음      | `원장 · 견주` | `승인`    |
| R-회원유형-03 | 0         | 있음      | `원장`        | `승인`    |
| R-회원유형-04 | 0         | 없음      | `일반 회원`   | `미보유`  |
| R-회원유형-05 | 0         | 해지됨    | `일반 회원`   | `미보유`  |
| R-회원유형-06 | 1         | 해지됨    | `견주`        | `미보유`  |

- 반려견 수는 지우지 않은 반려견만 센다. 원장 역할 '해지됨'은 없는 것으로 본다.
- 원장 상태는 `승인`·`미보유` 둘뿐이다. 판정 위치(서버가 원장·견주 여부를 줄지)는 새 API 스펙에 따른다.

## R-가림. 개인정보 가리기 (7.16, service-admin.html 기준)

판정: 서버. 입력: 종류, 원래 값. 기대값: 화면 값. `13-원장인증현황.md`도 이 표를 쓴다.

| ID        | 종류       | 원래 값                 | 화면 값                 |
| --------- | ---------- | ----------------------- | ----------------------- |
| R-가림-01 | 이메일     | `dog.owner@example.com` | `do*******@example.com` |
| R-가림-02 | 이메일     | `ab@example.com`        | `ab*@example.com`       |
| R-가림-03 | 이메일     | `a@example.com`         | `a*@example.com`        |
| R-가림-04 | 이메일     | `noatsign`              | (빈 값)                 |
| R-가림-05 | 이메일     | (없음)                  | (빈 값)                 |
| R-가림-06 | 전화       | `01098765432`           | `010-****-5432`         |
| R-가림-07 | 전화       | `010-9876-5432`         | `010-****-5432`         |
| R-가림-08 | 전화       | `1234567`               | `123-****-4567`         |
| R-가림-09 | 전화       | `123456`                | `***`                   |
| R-가림-10 | 전화       | (없음)                  | (빈 값)                 |
| R-가림-11 | 사업자번호 | `1234567890`            | `123-**-67890`          |
| R-가림-12 | 사업자번호 | `123-45-67890`          | `123-**-67890`          |
| R-가림-13 | 사업자번호 | `12345`                 | `***`                   |
| R-가림-14 | 사업자번호 | (없음)                  | (빈 값)                 |

- 이메일: `@` 앞 앞 2글자만 두고 나머지 글자 수만큼 `*`(최소 1개). `@`가 없으면 빈 값.
- 전화: 숫자만 뽑아 7자리 미만이면 `***`, 아니면 앞 3자리-`****`-뒤 4자리.
- 사업자번호: 숫자만 뽑아 10자리가 아니면 `***`, 맞으면 앞 3자리-`**`-뒤 5자리.
- 빈 값이 화면에 어떻게 보이는지는 각 S TC에 적었다(회원 칸 `연락처 미등록`, 인증 상세 `미등록`).

## 회원 목록 (7.16)

### S-회원-001. 회원 화면을 연다 (7.16, service-admin.html 기준)

- 실행: 브라우저 확인
- 로그인: 조회자
- 데이터: `회원-기본`
- 시작: 회원
- 행동: 화면을 연다
- 확인:
  - 제목 `회원 관리`, 아래 회색 `서비스 회원의 상태와 역할을 조회하고 관리합니다.`
  - 표 카드 위쪽 탭: `전체` · `견주` · `원장` · `탈퇴`, '전체' 선택(주황 밑줄)
  - 툴바 순서: 검색(안내 글자 `이름, 이메일 또는 회원 ID 검색`) → 가입일 드롭다운 → 오른쪽 끝 `총 6건` (PRD 4.4)
  - 표 열: 회원 | 회원 유형 | 계정 상태 | 원장 상태 | 가입일 | 최근 활동 | (이름 없는 열, 행마다 `⋯`)
  - 행 순서(가입일 최신순): U001, U002, U003, U004, U005, U006
  - 브레드크럼 없음, 사이드바 '고객 관리 > 회원' 강조 (4.2)
  - 브라우저 탭 제목 `회원 관리 · 똑독 BO` (4.2)

- 시작: 회원

    '처리 메모' 입력칸·'사용자 알림' 선택(`앱 알림과 이메일 발송`)·[취소]·[확인]이 함께 있고, [확인]이면 토스트
    `화면 초안이므로 실제 데이터는 변경되지 않았습니다.`
  - 2.2에서 고객 제재·탈퇴 처리는 제외다. `⋯`를 둘지, 창을 안내만 남길지 정해지지 않았다

## 사용성 검증 (2026-10-22)

근거: 사용자 요청에 따른 전체 TC 누락 점검 및 CONTRIBUTING.md 「화면 작업의 사용성 검증과 완료 기준」. 기존 기능 TC를

없으면 정상 응답과 1.5초 지연 응답을 각각 적용하고 첫 방문·재방문을 따로 확인한다. 자동 판정은 E2E로, 깜빡임·배치의
지각적 품질은 전환 중 DOM·위치·포커스·스크롤 관찰과 trace를 함께 보고 판단한다. TC 작성은 검증 통과를 뜻하지 않는다.
실행 결과·항목별 판정·관찰 자료는 `.local/test-results/`에 남긴다.

적용 범위: 목록 탭·검색·페이지·실패 복구·키보드. 조회 전용이므로 저장·초안·이탈 확인은 해당 없음. 가입일
필터·내보내기·행 메뉴·일부 검색 규칙의 기존 보류는 유지하고 아래 TC에서 새 동작을 확정하지 않는다.
