| R-표시명-02 | `김`                     | —                       | —              | 통과               |

| R-표시명-04 | `가나다라마바사아자차카` | —                       | —              | 오류               |
| R-표시명-05 | `이담당`                 | `이담당`                | —              | 오류               |

## 첫 로그인 프로필 설정 (7.2)

### S-내계정-001. 첫 로그인 프로필 설정 화면을 연다 (FR-BO-033)

- 실행: 브라우저 확인
- 로그인: 등록됨팀원
- 시작: 첫 로그인 직후 화면
- 행동: 화면을 연다
- 확인:
  - 사이드바 메뉴가 모두 흐리게 보인다
  - 상단바에 알림 아이콘·프로필이 없다
  - 본문 폭이 최대 520
  - 제목 `프로필 설정`, 아래 회색 한 줄 `처음 로그인하면 표시명과 직무를 정해야 BO를 쓸 수 있어요.`
  - 카드 순서: 구글 계정(`new@knockdog.test`, 읽기 전용) → 표시명*(`한새봄`, `3 / 10`) → 직무*(PM·UX/UI·FE·BE·풀스택) →
    [설정 완료]
  - 브라우저 탭 제목 `프로필 설정 · 똑독 BO`

### S-내계정-002. 완료 전에는 사이드바 메뉴로 이동할 수 없다 (FR-BO-033)

- 실행: E2E
- 로그인: 등록됨팀원
- 시작: 첫 로그인 프로필 설정
- 행동: 사이드바 '아이디어 제안' 클릭
- 확인:
  - 프로필 설정 화면 그대로

### S-내계정-003. 완료 전에 다른 주소로 가도 프로필 설정으로 돌아온다 (FR-BO-033)

- 실행: E2E
- 로그인: 등록됨팀원
- 시작: 첫 로그인 프로필 설정
- 준비: 표시명을 `새봄`으로 바꾼다
- 행동(경우마다 따로):
  - 주소 `/home`을 직접 입력
  - 새로고침
  - 브라우저 뒤로
  - 창을 닫았다가 새 창에서 BO 접속(같은 세션)
- 확인:
  - 이탈 확인창·브라우저 경고 없이 프로필 설정 화면이 다시 뜬다

### S-내계정-004. 표시명 칸이 구글 이름으로 채워지지 않는 경우 (7.2)

- 실행: E2E
- 로그인: 등록됨팀원
- API(경우마다 따로):
  - 구글 이름이 `가나다라마바사아자차카`(11자)
  - 구글 이름이 `이담당`(다른 팀원이 사용 중)
- 시작: 첫 로그인 프로필 설정
- 행동: 화면을 연다
- 확인:
  - 표시명 칸이 비어 있고 `0 / 10`

### S-내계정-005. 표시명이 잘못된 채로 [설정 완료]를 누른다 (FR-BO-031)

- 실행: E2E
- 로그인: 등록됨팀원
- 시작: 첫 로그인 프로필 설정
- 준비: 직무 `FE` 선택
- 행동(경우마다 따로):
  - 표시명을 비우고 [설정 완료]
  - 표시명 `가나다라마바사아자차카`(11자) 입력 후 [설정 완료] → 입력이 11자 그대로 남는다
- 확인:
  - 표시명 칸 빨강 + `표시명은 1~10자이며 이미 사용 중인 이름은 사용할 수 없습니다.`
  - 프로필 설정 화면 그대로

### S-내계정-006. 서버가 중복 표시명을 거부한다 (FR-BO-031)

- 실행: E2E
- 로그인: 등록됨팀원
- API: 설정 완료 요청이 표시명 중복으로 거부
- 시작: 첫 로그인 프로필 설정
- 준비: 표시명 `새봄`, 직무 `FE`
- 행동: [설정 완료] 클릭
- 확인:
  - 표시명 칸 빨강 + `표시명은 1~10자이며 이미 사용 중인 이름은 사용할 수 없습니다.`
  - 입력이 그대로 남는다

### S-내계정-007. 직무를 고르지 않고 [설정 완료]를 누른다 (FR-BO-032)

- 실행: E2E
- 로그인: 등록됨팀원
- 시작: 첫 로그인 프로필 설정
- 행동: 표시명 `한새봄` 그대로 [설정 완료] 클릭
- 확인:
  - 완료되지 않고 프로필 설정 화면 그대로(안내 문구 확인: OQ-P14)
  - 설정 완료 요청이 가지 않거나 거부된다

### S-내계정-008. 프로필 설정을 마친다 (FR-BO-033)

- 실행: E2E
- 로그인: 등록됨팀원
- 시작: 첫 로그인 프로필 설정
- 준비: 표시명 `한새봄` 그대로, 직무 `FE`
- 행동: [설정 완료] 클릭
- 확인:
  - 역할에 맞는 첫 메뉴(사이드바 첫 메뉴 '홈', `/home`)로 이동한다
  - 상단바 프로필 `한새봄 · FE`
  - 사이드바 메뉴를 누를 수 있다

### S-내계정-009. [설정 완료] 요청 중에는 다시 누를 수 없다

- 실행: E2E
- 로그인: 등록됨팀원
- API: 설정 완료 요청이 2초 늦게 응답
- 시작: 첫 로그인 프로필 설정
- 준비: 직무 `FE`
- 행동: [설정 완료]를 빠르게 두 번 클릭
- 확인:
  - 응답 전까지 [설정 완료] 비활성
  - 설정 완료 요청이 한 번만 간다

### S-내계정-010. [설정 완료] 저장이 실패한다

- 실행: E2E
- 로그인: 등록됨팀원
- API: 설정 완료 요청이 500 응답
- 시작: 첫 로그인 프로필 설정
- 준비: 표시명 `새봄`, 직무 `FE`
- 행동: [설정 완료] 클릭
- 확인:
  - 오류 토스트 `일시적 오류로 요청을 완료하지 못했습니다.`(닫을 때까지 남음)
  - 표시명 `새봄`, 직무 `FE` 그대로
  - [설정 완료]를 다시 누를 수 있다

### S-내계정-011. 한글을 조합하는 중에도 글자 수를 센다

  - 조합 중과 조합이 끝난 뒤 모두 `2 / 10`

## 프로필 패널 (7.15)

### S-내계정-012. 프로필 패널을 연다 (FR-BO-030)

- 실행: 브라우저 확인
- 로그인: 최고관리자
- 시작: `/home`
- 행동: 상단바 프로필 `김관리 · PM` 클릭
- 확인:
  - 아래로 팝오버가 열린다
  - 순서: `내 계정` → 구글 계정(`admin@knockdog.test`, 읽기 전용) → 표시명(`김관리`, `3 / 10`) → 직무(버튼형, `PM`
    선택됨) → 회색 `역할: 최고 관리자 · 역할은 최고 관리자가 바꿀 수 있습니다.` → 바닥 왼쪽 [로그아웃](빨간 글자),
    오른쪽 [저장]

### S-내계정-013. 표시명·직무를 바꿔 저장한다 (FR-BO-031, 032)

- 실행: E2E
- 로그인: 운영자
- 시작: `/home`
- 준비: 프로필 패널을 연다
- 행동(경우마다 따로):
  - 표시명을 `김운영2`로 바꾸고 [저장] → 상단바 `김운영2 · PM`
  - 직무만 `BE`로 바꾸고 [저장] → 상단바 `김운영 · BE`
- 확인:
  - 토스트 `프로필을 저장했습니다.`
  - 경우별 상단바 프로필
  - 패널을 다시 열면 저장한 값

### S-내계정-014. 표시명이 잘못된 채로 [저장]을 누른다 (FR-BO-031)

- 확인:

  - 상단바 프로필은 `김운영 · PM` 그대로

### S-내계정-020. 바꾼 것이 없으면 묻지 않고 닫힌다 (4.6)

## 사용성 검증 (2026-10-22)

근거: 사용자 요청에 따른 전체 TC 누락 점검 및
[웹 테스트 가이드](../testing-guide.md#화면-작업의-사용성-검증과-완료-기준). 기존 기능 TC를 보완하는 조작 품질 기준이다.
PRD OQ 결정 대기 항목의 기대값이나 새로운 PRD 기능을 확정하지 않는다. 실행 조건에 별도 표시가 없으면 정상 응답과 1.5초
지연 응답을 각각 적용하고 첫 방문·재방문을 따로 확인한다. 자동 판정은 E2E로, 깜빡임·배치의 지각적 품질은 전환 중
DOM·위치·포커스·스크롤 관찰과 trace를 함께 보고 판단한다. TC 작성은 검증 통과를 뜻하지 않는다. 실행 결과·항목별
판정·관찰 자료는 Git에서 제외된 로컬 검증 결과 폴더에 남긴다.

적용 범위: 첫 프로필 설정·프로필 패널의 입력, 저장, 닫기와 이탈 확인. 목록 검색·페이지는 없는 화면이므로 해당 없음.

### S-내계정-023. 표시명 조합 입력·검증 중 입력 위치를 유지한다

- 실행: E2E
- 로그인(경우마다 따로): 등록됨팀원 / 운영자
- 시작: 첫 프로필 설정 / 상단바 프로필 패널(로그인 계정에 대응)

- 행동: 한글 조합과 중간 삽입·삭제로 10자 경계를 오가고 오류를 수정한다

  - 입력 즉시 글자·글자 수·검증 결과가 일치하고 조합 중 커서·포커스가 초기화되지 않는다
  - 오류 안내가 생기거나 사라질 때 입력·직무 버튼이 불필요하게 이동하지 않는다
  - 저장 거부 후에도 입력값을 고칠 수 있고 오류 대상을 알아볼 수 있다
  - 조합 상태는 S-내계정-011처럼 재현하고 실제 IME 품질은 별도 관찰 근거를 남긴다

### S-내계정-024. 저장 지연·실패 중 편집 내용과 표시가 일관된다

- 실행: E2E
- 로그인(경우마다 따로): 등록됨팀원 / 운영자
- API: 프로필 설정·저장 1.5초 지연 후 성공 / 500 / 표시명 중복 거부(경우마다 따로)
- 시작: 첫 프로필 설정 / 상단바 프로필 패널(로그인 계정에 대응)
- 준비: 표시명 `새봄`, 직무 `FE` 입력
- 행동: 저장을 연속 누르고 대기 중 표시명·직무 변경을 시도한다
- 확인:
  - 진행 상태를 알 수 있고 같은 저장이 중복 실행되지 않는다
  - 대기 중 편집을 제한하면 이유를 알 수 있고 허용하면 새 편집이 이전 성공 응답으로 소실되지 않는다
  - 실패 시 값·초점·작업 위치를 보존하고 재시도할 수 있다. 상단바에는 저장 전 프로필이 남는다
  - 성공 시 상단바·재개방 패널·첫 설정 완료 상태가 저장한 값과 일치하고 불필요한 이탈 경고가 없다

### S-내계정-025. 패널과 이탈 확인 사이에서 작업 맥락을 유지한다

- 행동: Esc 또는 바깥 클릭으로 이탈 확인을 열고 [취소]한다(경우마다 따로)

  - 변경 없는 패널은 경고 없이 닫히고 연 프로필 버튼으로 초점이 돌아온다
