# TC 작성 규칙

이 문서는 웹 TC의 근거, 분류, 작성 양식과 표기 규칙을 정의한다. 실행 범위 선정과 검증 완료 판정은 별도 문서에서
관리한다. 개별 TC와 공통 데이터 정의는 `tc/` 폴더에 둔다. 현재 파일 목록·TC 개수·날짜별 점검 현황은 이 문서에 기록하지
않는다.

## 1. 요구사항과 기대 결과 확인

- 기능 TC는 PRD의 요구사항을 근거로 작성한다. 제목 끝 괄호에 해당 절 번호나 FR 번호를 적는다.
- PRD에 없는 동작이나 결정되지 않은 기대값을 임의로 만들지 않는다. 누락·모순·선택지는 PRD의 OQ에 등록하거나 기존 ID에
  연결하고, TC에는 `(결정 대기: OQ-ID)`를 남긴다. TC에만 독립적인 보류 사유를 두지 않는다.
- 사용자 결정 후에는 PRD 본문·OQ 상태·TC 기대값을 함께 갱신한다. 범위 제외·결정 대기·외부 연동 대기를 구분하고, 미확정
  항목을 통과로 집계하지 않는다.
- 사용성 기준이나 사용자 피드백에 따른 회귀 TC는 기능 요구사항과 구분하고, 근거와 필요한 경우 날짜를 적는다.

## 2. TC 분류와 ID 지정

| 분류         | 작성 대상                                                         | ID 형식         | 실행 방식                          |
| ------------ | ----------------------------------------------------------------- | --------------- | ---------------------------------- |
| 규칙(R)      | 화면 없이 입력과 출력으로 판정할 수 있는 권한·검증·상태 전환 규칙 | `R-<규칙명>-NN` | Vitest                             |
| 화면 동작(S) | 한 화면에서 준비 상태·행동·결과를 확인하는 경우                   | `S-<기능>-NNN`  | TC에 명시한 E2E·브라우저 확인·수동 |
| 흐름(F)      | 여러 단계나 화면에 걸쳐 이어지는 사용자 시나리오                  | `F-<기능>-NN`   | Playwright E2E                     |

- 한 문서 안에서는 규칙(R) → 화면 동작(S) → 흐름(F) 순서로 작성한다.
- 기존 기능명과 ID를 확인해 일관되게 사용하고, 새 항목에 중복되지 않는 ID를 부여한다.
- 여러 화면의 공통 정책은 공통 TC에서 정의한다. 화면별 TC에는 그 화면에 적용되는 조작과 결과를 구체화하고, 공통 권한 표
  전체를 반복해서 복사하지 않는다.

## 3. 데이터와 준비 조건 정의

- `로그인:`과 `데이터:`에는 공통 데이터 정의인 `tc/fixtures.md`의 계정·묶음 이름을 쓴다. 없는 계정이나 결과값을 TC
  안에서 임의로 만들지 않는다.
- 가짜 API는 `데이터:`의 묶음과 공통 팀원 묶음을 먼저 넣고, `로그인:` 계정의 세션으로 시작한다. 여러 데이터 묶음은
  쉼표로 나열한다.
- `API:`에는 기본 데이터로 표현할 수 없는 응답 변경만 적는다. 상태 코드와 본문은 API 계약에 맞추고, 데이터를 넣은 뒤
  해당 요청의 응답을 덮어쓴다.
- 기준 시각과 기본 창 크기는 공통 데이터 정의를 따른다. 특정 시각·크기에서 확인할 때만 TC에서 명시적으로 바꾼다.
- 번호·이름·시각·목록 순서 등 기대값은 데이터 정의에서 가져온다. 데이터가 바뀌면 그 데이터를 사용하는 TC의 기대값도 함께
  갱신한다.

## 4. 분류별 작성 양식

### 규칙(R): 입력과 기대값을 표로 작성

표 위에 입력 열과 기대값 열, 판정 주체를 설명한다. ID 뒤의 열에는 입력값 또는 기대값만 두고, 추가 설명은 표 아래에
적는다.

```markdown
## R-문의상태. 문의 상태 전환 (PRD 5.2)

입력: 현재 상태·현재 담당자·일어난 일. 기대값: 다음 상태·다음 담당자.

| ID            | 현재 상태 | 현재 담당자 | 일어난 일 | 다음 상태 | 다음 담당자 |
| ------------- | --------- | ----------- | --------- | --------- | ----------- |
| R-문의상태-01 | 답변 대기 | 미배정      | 맡기      | 확인 중   | 나          |
```

- 한 줄을 하나의 경우로 작성하고 Vitest `test.each`의 입력과 기대값에 대응시킨다.
- 서버가 판정하는 규칙이면 `판정: 서버`를 명시한다. MSW 검사는 가짜 서버가 규칙을 따르는지 확인하는 것이며, 실제 서버
  연동 검증과 구분한다.
- 기대값이 미정인 줄은 OQ ID와 결정 대기 상태를 표시하고 실행 시 건너뛴다. 실행 가능한 규칙만 통과·실패로 판정한다.

### 화면 동작(S): 조건 → 행동 → 결과로 작성

```markdown
### S-문의-029. 미배정 문의를 맡는다 (FR-BO-053)

- 실행: E2E
- 로그인: 운영자
- 데이터: `문의-기본`
- 시작: 문의 상세(#1041)
- 행동: [내가 맡기] 클릭
- 확인:
  - 토스트 `문의를 맡았습니다.`
  - 상태 배지 '확인 중'
```

| 항목      | 필수   | 작성 내용                                              |
| --------- | ------ | ------------------------------------------------------ |
| `실행:`   | 예     | `E2E`, `브라우저 확인`, `수동 (이유)` 중 하나          |
| `로그인:` | 예     | 공통 데이터 정의의 계정 이름. 비로그인은 `없음`        |
| `데이터:` | 아니오 | 공통 팀원 묶음 외에 필요한 데이터 묶음                 |
| `시각:`   | 아니오 | 기본 기준 시각과 다른 경우의 시각                      |
| `창:`     | 아니오 | 기본값과 다른 브라우저 창 크기                         |
| `API:`    | 아니오 | 해당 요청에 적용할 지연·실패·응답 변경                 |
| `시작:`   | 예     | 실제 화면 이름이나 구현된 라우트. 주소를 지어내지 않음 |
| `준비:`   | 아니오 | 행동 전에 필요한 화면 조작                             |
| `행동:`   | 예     | 확인할 행동 하나                                       |
| `확인:`   | 예     | 행동에 따른 사용자에게 보이는 결과                     |

실행 방식은 확인할 결과에 따라 고른다.

| 실행 방식       | 작성 대상                                                                             | 남길 근거                                                    |
| --------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `E2E`           | 상태·저장 결과, 권한·세션 제한, 경합, 조회·저장 실패와 복구                           | Playwright 검사 코드와 결과                                  |
| `브라우저 확인` | 문구·표 열·배치·빈 상태 등 눈으로 확인하는 구성                                       | 관찰 근거. 문구·배치 확인만을 위한 테스트 코드는 만들지 않음 |
| `수동 (이유)`   | 실제 구글 로그인, 외부 알림 도착, 실제 서버 저장 등 모의 환경으로 확인할 수 없는 결과 | 실제 환경에서의 확인 근거 또는 미확인 사유                   |

- 상태 변경과 문구·배치가 섞이면 상태·저장 결과를 중심으로 E2E를 작성한다. 순수 문구·배치 확인은 별도 브라우저 확인
  항목으로 나눈다.
- 뒤로 가기·새로고침·주소 직접 입력·Esc·창 크기·시각 변경·네트워크 실패는 Playwright로 재현할 수 있다. 이런 조작이
  있다는 이유만으로 수동 항목으로 분류하지 않는다.
- 정적 구성은 `행동: 화면을 연다`로 작성한다. 화면별 실패·경합·이탈 정책은 해당 화면의 구체적인 조작과 결과를 적는다.

### 흐름(F): 단계별 행동과 결과를 연결

```markdown
### F-문의-01. 맡아서 답하고 추가 문의를 받는다 (PRD 3.3)

- 로그인: 운영자
- 데이터: `문의-기본`

1. 문의 상세(#1041)에서 [내가 맡기] → 확인 중
2. 답변 입력 후 [답변 저장] → 답변 도착
3. (가짜 API) 사용자 추가 문의 등록 → 목록에서 답변 대기, 담당자 나
```

- 각 단계는 `행동 → 확인할 결과`로 적는다.
- `(가짜 API)`는 앱 사용자 등 다른 주체의 동작을 가짜 서버 상태로 재현한다는 뜻이다.
- 가짜 API는 단계 사이에서 변경된 상태를 유지해야 한다.

## 5. 사용성·실패 복구 조건 구체화

- 준비 조건, 사용자 조작, 진행 중 기대 결과, 완료·실패 후 기대 결과를 적는다.
- 정상·지연 응답, 빠른 연속 조작 등 결함을 재현하는 데 필요한 조건을 명시한다. 가능한 모든 조건의 조합을 일괄로 늘리지
  않는다.
- 깜빡임·배치 이동·포커스·스크롤·입력값·상태 일관성·실패 복구 중 변경에 해당하는 위험을 사용자에게 보이는 결과로
  표현한다. 특정 훅이나 DOM 유지 방식 자체를 기대값으로 강제하지 않는다.
- 예를 들어 `검색 입력 중 커서가 유지되고 마지막 검색어의 결과가 표시된다`처럼 조작 중의 기대 결과를 적는다.

## 6. 여러 경우와 미확정 항목 표기

- 계정·응답·시각 등 한 조건에 여러 값이 필요하면 해당 줄에 `(경우마다 따로)`를 적고 값별 기대 결과를 나열한다. 실행 시
  `test.each`나 반복문으로 각 경우를 구분한다.
- R 표를 입력으로 참조하는 S TC는 표의 각 줄에 대응하는 경우를 구분한다.
- 준비·행동의 `A → B`는 순서를 뜻한다. `확인:`의 `이어서 …`는 같은 TC 안에서 추가 조작과 결과를 확인한다는 뜻이다.

| 표기                     | 의미                                                                                |
| ------------------------ | ----------------------------------------------------------------------------------- |
| `—`                      | 해당 없음                                                                           |
| `(결정 대기: OQ-ID)`     | 기대값 미정. 결정 후 PRD와 TC를 함께 갱신                                           |
| `(문구 확인: OQ-ID)`     | 표시 필요성은 정해졌지만 정확한 문구는 미정. 임의의 문자열을 정답으로 고정하지 않음 |
| `(범위 제외: 근거)`      | 합의된 구현·검증 범위에서 제외                                                      |
| `(외부 연동 대기: 대상)` | 실제 외부 환경에서의 결과 확인이 남아 있음                                          |
| `[버튼]`                 | 버튼 이름                                                                           |
| `'글자'`                 | 메뉴·배지·탭 등 화면 요소의 표시값                                                  |
| 백틱 안의 글자           | 화면에 표시되는 문구 또는 식별자                                                    |
